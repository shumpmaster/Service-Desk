Ruling: in Service Desk, the Orchestrator's asks-merge workflow may merge pull requests that only file or close a question file, tidy away one already answered, or add the Chief of Staff's session lines, once every check is green; the permission stands until the owner withdraws it
Proxy: done at the owner's request (the owner answered in the session on 2026-10-17, multiple choice, while the operating model's S-033 was planned; the selection and the option texts are quoted verbatim below, as recorded in the model's reviews/S-033/_owner-answers.md, answer 1)

Question, as put: "The desk only sees records on a project's main branch. Today an agent's question to you reaches main only when you merge a pull request, so an ask in chat is invisible on the desk while it's open. How should a filed ask get onto the desk?"

Options, as put:
- "Agents merge asks (Recommended)": "A standing permission, narrower than the overnight one: the Orchestrator may merge pull requests that only add or close a question file, or add the Chief of Staff's session records, once every check is green. The ask shows on the desk within minutes. Your answer is still your words, quoted exactly. Code, specs, deploys and verdicts still wait for you. You can withdraw it any time."
- "You merge each ask": "No new permission. Each ask arrives as a small pull request: you merge it, then answer. One extra tap per ask, and the desk shows it only after you merge."
- "Desk reads unmerged asks": "No new permission and no extra tap. The desk is changed to also read question files in open pull requests. That's more desk work, and it ties the desk to how pull requests are named."
- "Record after only": "Asks stay in chat. Each answer is recorded with the time it was asked and answered, so the counts are right afterwards, but the desk still can't show an ask while it's open."

The owner's answer: "Agents merge asks (Recommended)".
