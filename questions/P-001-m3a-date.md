# Ruling needed: In Work ahead, what kind of date does each milestone get?

Milestone: M3A

WHY: Each row in the Work ahead mockup has one date box. The spec change needs to know what that date means. Leaving it unruled holds the M3A spec change.
OPTIONS:
  A. A date to aim for — When you'd like the milestone reached; the row turns coral once the date passes.
  B. A "not before" date — When work on it may start, as the spec has it today.
  C. Both — Two date boxes per row.
RECOMMENDATION: A — you set goals by the date you want them done, like the 11 November launch.
RISK CLASS: R0   REVERSIBILITY: reversible   BLAST RADIUS: the M3A spec change and the Work ahead screen only
DEFAULT: A   TIMEOUT: 48

## Context
- The spec's Work ahead today gives items a "not before" date and time (source: specs/S-001.md, AC24; J4's content table)
- The launch target, V4, is a date to reach: 2026-11-11 (source: docs/PROJECT.md, section 6)
- The mockup shows one "Aim for" box per milestone, with M3C's set to 11 November (source: docs/design/mockups/work-ahead.html)
