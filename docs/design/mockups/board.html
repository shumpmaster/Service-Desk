Waiting on you, as a board

What waits on you, and Done. Each card has one button, for the one step that clears it, opening GitHub as prefilled as GitHub allows. When you've done it, drag the card to Done (on a phone, press and hold first), or tap "Done ✓". It is done at once and leaves the count; a small grey note says the desk is confirming it with GitHub, and goes when GitHub agrees. If after about 5 minutes GitHub still doesn't show that step, the card is kicked back, with the reason. The cards are today's real items. Try it in any frame: the demo fakes GitHub's answer in seconds, not minutes; #128 is kicked back the first time, and GitHub "confirms" it by itself a little later.

"Kicked back" is your word; the name is yours to confirm. Your other example was "Hung up".

At 700px and wider

The same board on a tablet or computer: three columns, Waiting on you, Kicked back and Done. (On a phone this frame shows the phone layout.)

How each card's one step is chosen

  • Merge on GitHub opens the pull request's page, where GitHub's merge button is. For a pull request that needs nothing else from you.
  • Add your verdict opens GitHub's new-file page for reviews/<n>/owner.md on the pull request's branch, with "Verdict: PASS" filled in. Only for a pull request whose risk class needs your verdict (R3). It reads "Step 1 of 2: add your verdict"; once confirmed, a new card, "Step 2 of 2: merge", appears.
  • Answer opens the answer file for a question, filled in with the question and its options; you put your letter after "Ruling:".
  • Approve the deploy opens the deploy run that is waiting for your approval.
  • Pull requests the automatic job merges itself are never cards: they are counted in the quiet line under Done.

How each card is confirmed

Your Done counts at once. The desk then checks the one step, as often as it reads GitHub:

  • Merge on GitHub: GitHub shows the pull request merged.
  • Add your verdict: reviews/<n>/owner.md is on the pull request's branch.
  • Answer: the answer file is on the main branch, or a pull request adding it is open.
  • Approve the deploy: the deploy run is no longer waiting.
  • If GitHub still doesn't show the step after about 5 minutes, the card leaves Done for Kicked back, with the reason and its one button, and counts again. From there you drag it to Done or tap "Done ✓" again; if GitHub shows the step later on its own, it goes to Done by itself.
