# Ruling needed: May a copy of the widget test's data leave your phone, and by which route?

Milestone: none (the widget's milestone, M5, is still only a proposal in its plan, so nothing here serves a milestone yet)
Asked in session: session_01QBwHGNFKViyibzxHx5qTtm

WHY: The test widget is built and checked, but its written plan can't be locked before it runs until you rule on this. To check that the widget showed the right summary on your phone, the team member who checks the work (the Reviewer, who did not make it) needs a copy of what GitHub told the widget at each refresh. That copy holds your projects' records, including the two private ones (Personal-Org-Operating-Model and portfolio). Your earlier ruling, "Phone only", keeps the widget's records on the phone. So any route that brings the copy back is a one-off exception to that ruling, for this test only, and that exception is what you are asked to allow or refuse. The desk's other rule, that your project content goes only to GitHub and Cloudflare, can still be kept. The route first drafted had you upload the copy to Service-Desk, which is a public repository, so it would have published your private projects' records. That route is withdrawn. Nothing on the desk changes whichever you choose.
OPTIONS:
  A. "Widget sends it to portfolio (Recommended)" — "One exception to Phone only: at the end of the test you tap "Send the test data", and the widget sends its copy straight to a new branch of your private portfolio repository on GitHub. It needs a second key, kept in the iPhone keychain like the first, that can write files only in portfolio (7-day expiry, deleted after); a key that can write portfolio's files could also change its main branch, which the desk reads, so a fault in the widget could change what the desk shows from portfolio. The copy never goes into your phone's Files, so your phone's iCloud backup doesn't pick it up. The Reviewer then downloads it into its working session to check it, as it already does with your repositories. Costs: a widget change, its check again, and about 5 more minutes of your time."
  B. "You upload it to portfolio" — "One exception to Phone only, and to the desk's rule: you save the copy in Files (On My iPhone), upload it to a new branch of portfolio on github.com, then delete it and empty Files' Recently Deleted, which otherwise keeps it for 30 days. While the file is in Files, an iCloud backup may copy it, and that copy stays in Apple's iCloud until the backup is replaced, usually for days. You can avoid that by turning iCloud Backup off until the file is deleted. About 10 minutes."
  C. "Check timing only" — "No exception: the copy never leaves the phone. Only the log comes back, and it holds counts, project names and scrambled stand-ins for titles, no records. The test still checks that later refreshes finish and how long they take, but not whether each summary was right; that is checked later only by the desk's own test on sample records. This changes the pass mark the plan sets."
  D. "Pause the test" — "Stop here. The test widget exists only in this session's working copy, so it would have to be rebuilt in a later session."
RECOMMENDATION: A, because it keeps the test as planned, keeps your records on GitHub, in a private repository, and keeps them out of your phone's iCloud backup. My confidence is medium: the widget change is small, but it still has to pass its check. It would change if you'd rather no key that can write to GitHub exist on your phone, even one limited to portfolio for a week; then B, with iCloud Backup off, is the next best.
RISK CLASS: R0   REVERSIBILITY: reversible   BLAST RADIUS: only the widget test's steps and its written plan; nothing the desk does or shows. Portfolio has no workflows, and the desk reads only its main branch, so a test branch there starts nothing and shows nowhere. The ruling can be changed later, but what a route does can't be fully undone: commits on a deleted branch can still be fetched for a while by you and anything you have given read access to portfolio, including the GitHub access these sessions use, and under B, a backup copy lasts until it is replaced.
DEFAULT: none   TIMEOUT: none (a departure from the usual default: a ruling on where your project content goes is not taken by default)

## Also for you to know, whichever you choose
- The log, the second file, holds no records. Under A it goes to the same portfolio branch; under B you upload it with the copy; under C you save it in Files and upload it on github.com to a new branch of portfolio, the only file that leaves the phone.
- Up to about 20 MB of the widget's records stay in Scriptable's own cache on the phone after the test, which the backup skips. Today the widget has no menu item that deletes them. A change now being made to it, which every route but D gets, adds a last item, "Delete test data", that deletes them along with its log and what it kept; it is checked before the test is given to you.
