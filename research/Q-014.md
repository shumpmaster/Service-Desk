# Research question — Q-014

*Asked by the Orchestrator on 2026-10-18, for the notifications amendment (Critic round 2, B3: "A load-bearing GitHub behaviour has no source and no fallback").*

## The question

For a workflow started by `on: workflow_run` in a public repository, whose job uses an Environment limited to `main`:
1. what are `github.ref`, `github.ref_name` and the run's own `head_branch`, and which code runs;
2. does a main-only deployment-branch rule admit the job when the triggering run was on another branch or a fork, and has that changed;
3. under which branch does the runs list file such runs;
4. do fork-triggered runs reach repository and Environment secrets, and what does GitHub say about the risk;
5. are `schedule` and `workflow_dispatch` on main admitted;
6. what pattern does GitHub recommend.

Answer from GitHub's own documentation, changelog and staff answers, dated and graded.
