# Research question — Q-019

*Drafted by the Chief of Staff; checked by the Critic for gaps and neutral phrasing (D-032, D-055).*

## The question

What does the desk already show, and already read, for pull requests and other changes, and which existing records tie a pull request to the milestone, sprint, spec or plan it belongs to?

The desk (shumpmaster/Service-Desk) is a status page for one owner across several project repositories and a portfolio repository. In v3 projects a pull-request description must carry a line naming the milestone it serves (shumpmaster/Personal-Org-Operating-Model, OPERATING_MODEL.md §3 "Why and context", S-032); the rule binds from the model version that introduced it, and older pull requests were not rewritten. A project's own milestones are listed in section 3 of its project document, one per line, in a form that begins `<name> (M<id>) · done when <what is achieved> · phase: <phase>` and ends ` · why: <reason>`, among other parts, with ` · sprints: PR #40, PR #41` when built outside the pipeline (Personal-Org-Operating-Model, template-v3/docs/PROJECT.md, section 3: the model's template file, which may be read). The groundwork map left open what the desk's pull-request rows show and whether merged changes appear on the desk at all (research/Q-016-memo.md, areas A3, A4, H2, K2, K3 and N1).

What may be read: Service-Desk's src/, docs/handover/, reviews/, status/, dispatch-log/ and queue/; Personal-Org-Operating-Model's OPERATING_MODEL.md, specs/ and template-v3/; the GitHub pages of Service-Desk's pull requests. Not to be read: any repository's decisions/, questions/, docs/PROJECT.md, docs/reports/ or docs/briefs/; Model-Lab; the portfolio repository's contents. Where a record that would answer a bullet is in a place not to be read, say so and do not answer that part. Say for each finding which file and lines show it.

- For a pull request waiting on the owner, and for one already merged: does it appear on the desk, where, with what words and links, and what decides that it appears?
- Which parts of a pull request the desk reads (its title, its description or any section of it, its diff, its commits, its checks, its reviews, its labels, its linked records), and which it shows.
- How the desk decides that a pull request waits on the owner, and which kinds of waiting change it would not list.
- Whether the desk shows changes that are not pull requests (deploys, direct commits, record-only commits), and what it shows for them.
- Whether the desk shows when each row was last refreshed, and what it does when a pull request changes after it is listed.
- For each project, whether a phone notification is sent, and whether it covers merged changes as well as waiting ones.
- What records tie a pull request to a milestone, a sprint, a spec or a project's plan (for example, the description's milestone line, the milestone list's ` · sprints:` part, spec headers, status or dispatch-log files, review records, merge commits as shown on the pull-request page); and for two stated samples read from their GitHub pages (the open pull requests and the last ten merged in Service-Desk; and ten merged in Service-Desk's first two weeks, from 2026-09-30), how often each is filled.
- What the desk shows about a project's milestones and progress, and whether any of it names the pull requests behind it.
- Whether the desk keeps any mark of what the owner has seen or done, and whether it is kept on one device or shared.

## The decision it serves

Whether the desk and the projects' records already do what any new way of keeping up with changes would do; what such a way would then replace, duplicate or add to; and which existing records it could draw on.

## What each answer would change

What the desk already shows and reads sets what a new way of keeping up would replace, duplicate or add to, or whether none is needed. What the records tie together, and how reliably, sets what any use of them could rely on and where they are silent. An existing mark of what the owner has seen sets what exists to build on or leave alone.
