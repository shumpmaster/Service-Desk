# Design references: the owner's screenshots and direction

These are the screenshots the owner chose as inspiration for the desk's screens. Each one sits
next to the owner's own words about it, so a design session can start from them without the
conversation in which they were sent. When a new reference arrives, add it here before
designing from it.

The screenshots are of other companies' apps, curated by Mobbin. They are kept for internal
design reference only.

## What the owner added afterwards (9 Oct 2026, verbatim)

**Team (screen 3).** "This page was more about the agent dashboard. All the agents in one place
showing status etc… I agree - no made up numbers or scores - the visual was just appealing."

"In my head the agent dashboard is just a panel that lights up where an agent is working
something, or recently has finished something and it becomes a way to quickly click into an
agent and see the work they've performed."

**Timeline (screen 4).** "no need to have things spaced by any real durations. The idea is just
in general one timeline that shows what has been done, in what order, with reviews, blockers, re
issues all progressing toward milestones - ultimately rolling up to the operating model phases."

"I'm okay with us going back into a phase I just want to visualize it as a development required
iteration."

**Milestones.** "Milestones should be established project by project, but I want them to be lead
with plain English."

**Breakdown (screen 5).** "Absolutely no fake numbers. N+2 to me is like the second level of a
work breakdown structure."

**Queue (screen 6).** "I actually think the groups map to the type of action needed. Keep in mind
I don't like to "cross boundaries" when I work. I want each of my projects and everything within
them retained within their respective tile on that front page. Eventually I might expand on that
but not right now. And agreed on the 2 taps."

**Confirmation.** "when i confirm something its in relation to the timeline. So if i commit a PR -
the visual feedback is the PR on the timeline getting checked off or something."

**Purpose.** "These builds arent going to be measured on anything. They are designed to be a clean
easy to grasp interactive interface that simulates a full build team and puts me at the top as
the boss - and most importantly conveys the technical information to me in a way i can understand
and decide when to push/pull on threads." The owner also said: "i am just trying t avoid any
scenarios where i get completely confused at terminology - what were doing - why - what it means".

## Feedback on lab page 4 (9 Oct 2026, the owner's comments)

- Plan and steer: "A new project doesn't really belong here. Remember we focus on projects."
- "Generally speaking I don't love the health page."
- "I think usage belongs with the agent hub screen … there should be an overall usage number,
  then specific usage should be visible in the agent specific pages"
- Quiet and problems: "I like the conciseness here … I like the icon usage, but again remember
  they should be integrated into the other screens I had sent you as inspiration"
- Overall: "it all lacks an interconnectedness". The owner said: "I want to build page by page …
  You built elements not full views and i was thinking in full views."

## How to work from this

Build one full screen at a time, in the order above, each matched to its reference. Fit each
element (agent detail, usage, quiet and problem states, the plain-language layer) into the
screen it belongs to. Don't give an element a page of its own.
