3. **The Source checker's bar is stricter than the question.** It requires two independent sources for load-bearing facts, and "an unverifiable claim is a FAIL".
   - The question's depth line was "graded memo; counts from a fixed sample", and it never asked for two sources.
   - A memo that honestly marks items "could not be determined" will therefore predictably fail a check that wants two sources per load-bearing fact.

4. **Where the chain stops.**
   - **Root cause: stage 2, question design.** The question set a task (a deep PR-by-PR audit, depth 3) that the Researcher's tools could not meet to the Source checker's standard. The round-2 Critic saw the tool risk and rated it non-blocking.

   - **Contributing factor, Source checker:** it stopped partway ("I have enough for a verdict"). It counted facts it did not re-open as unconfirmed, which is not the same as contradicted.
   - **Not at fault:** the question's neutral phrasing and its Service-Desk-only scope. Both held up.

5. **Routing.**
   - **Route to the Chief of Staff** to revise the question. Either:
     - narrow it, for example to fewer pull requests, or to what the page tools can read (descriptions and the `.diff` pages), with the rest marked "not assessable"; or
     - have the owner supply a route that can fetch the data (authenticated `gh` or GraphQL, for the true commit lists and `userContentEdits`).

   - A fresh Critic then re-checks the revised question.
   - Do not send this back to the Researcher alone. Re-running the same question with the same tools is a re-run (D-047) and would fail the same way.
