## The question

From published documentation only: what are the ways a single-user web page, hosted on Cloudflare Pages with Pages Functions behind Cloudflare Access, can send its owner a phone notification when something needs them while the page is closed?

Cover:
- Web Push from an installed home-screen web app on iOS (Safari) and Android (Chrome): the requirements (installation, service worker, permission prompt, VAPID keys), what a sender needs on the server side, and whether a subscription can be stored and a push sent without a database (e.g. Cloudflare KV, Durable Objects, or a secret);
- what triggers a send when nothing is polling: Cloudflare Cron Triggers on Workers or Pages, or a GitHub Actions workflow;
- how Cloudflare Access affects a service worker's registration and the push click-through;
- the GitHub mobile app's notifications for issues assigned to the user, as an alternative channel: what triggers them, their latency, and the controls the user has;
- documented limits, costs on free plans, and what the platforms say about notification permission and fatigue.

Use only public documentation, changelogs and official announcements (Apple, Google, the W3C or IETF Push specifications, Cloudflare, GitHub), read through web search and web fetch. Do not inspect this session's own environment, configuration, files outside the brief, or any credential. Where the documentation does not say, write "not documented" rather than testing it. Report a fact as confirmed only where two different pages state it; list facts stated on one page only, or on none, separately as "single page" or "not documented", and make no cost or quality recommendations.

The decision it serves: how the owner is told about waits while the Service Desk is closed (the owner's answer: "Phone notifications", decisions/questions/P-001-design-discovery.md), within the desk's rule of no server-side state (S-001) or a ruled exception to it.

Depth: 3, a graded memo. Topics: notifications, web-push, cloudflare, github.
