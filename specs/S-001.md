## Terms used in this spec
- **Connected project:** an entry in the desk's repository list (`config/projects.json`, J7), with
  the read token able to read it. At launch: Service-Desk and Personal-Org-Operating-Model.
  Sized for up to 5.
- **Card:** a file `queue/<item>-<gate>-<n>.md` in a connected project. Its **answer** is the file
  `decisions/<item>/<gate>-<n>.md` in the same repository. Evidence for the pairing:
  `queue/Q-003-failure-1.md` (PROJECT.md:507) and the answer files `decisions/P-001/dor-fail-1.md`,
  `decisions/P-001/failure-5.md` (this pack); the pairing rule is inferred (C) and is fixed in J2.
- **Open card:** a card with no answer file on the default branch.
- **Needs the owner (flagged):** an open card, or an open pull request with a review requested
  from the owner's GitHub login. Nothing else is flagged (PROJECT.md §8 "Needs the owner"; Part 2
  "Only flag what needs a human").
- **Activity:** anything shown but not flagged: CI runs, agent sessions, dispatches, open PRs not
  awaiting the owner.
- **Open window:** a span during which the desk page is visible in the foreground on a device
  (the browser's page-visibility state is "visible").
- **Quiet:** no flagged item in any connected project, **and** every connected project read
  successfully within the last 3 minutes.

## Acceptance criteria (scenarios; owner-approved)
Each criterion is a plain scenario. "Within 5 minutes" is V1's figure. Screen width for "phone" is
360 CSS pixels; for "desktop", 1280.

**Seeing what needs you (D2, D3.1)**
- AC1 [trace: V1 → AC1] — When a card is committed to a connected project's default branch while
  the desk is open on the owner's phone, then within 5 minutes the project's box shows it as
  waiting on the owner and the box moves to the top of the Universe screen.
- AC2 [trace: V1 → AC2] — When the owner opens the desk after it was closed, then until every
  connected project has been read once since opening, the screen says "Checking…" and never
  "Quiet"; once all are read, every open card in every connected project is shown.
- AC3 [trace: V1 → AC3] — When a connected project can't be read (token rejected or expired,
  GitHub rate limit, GitHub or Cloudflare error, or no successful read for 3 minutes), then its
  box says "Can't read since HH:MM" with the reason, sorts above every box except those with
  flagged items, and the screen as a whole does not say "Quiet".
- AC4 [trace: V2 → AC4] — When a connected project has a failing CI run, an agent retrying, a new
  dispatch, or an open pull request with no review requested from the owner, then the desk shows
  it as activity in that project's box and does **not** flag it, count it as waiting, or move the
  box up for it.
- AC5 [trace: V2 → AC5] — When a card's answer file is committed (by any route), then within 5
  minutes the desk stops flagging that card while open, and on next opening it is not flagged.
- AC6 [trace: V4 → AC6] — When the owner looks at the Universe screen, then each connected
  project has one box showing its state (flagged count, or "Can't read", or quiet), its headline,
  its current sprint and its main-branch CI result, ordered worst first: flagged, then
  can't-read, then main branch failing, then the rest by name.
- AC7 [trace: V4 → AC7] — When the desk runs on the preview for 7 consecutive days before launch,
  then each day the Chief of Staff compares it with the Operations-Hub page and finds no item the
  old page shows as needing the owner that the desk does not flag ("at least as correct", §1).
  Differences are logged in `docs/LEDGER.md`; one unexplained difference resets the count.

**Reading and answering (D3.2, D4.1)**
- AC8 [trace: V1 → AC8] — When the owner taps a flagged card on the phone, then its full text is
  shown, with every option it offers, rendered from its markdown, without sideways scrolling.
- AC9 [trace: V4 → AC9] — When the owner picks an option on a card (and optionally types a note),
  then the desk opens GitHub's new-file page for that card's repository and default branch, with
  the file name `decisions/<item>/<gate>-<n>.md` and the content in J3's form filled in, and the
  owner commits it there. The desk itself writes nothing to GitHub.
- AC10 [trace: V4 → AC10] — When the prefilled link would be longer than 6,000 characters, or
  EXP-004 found the content prefill not working for that repository, then the desk instead shows
  the answer text with a "Copy" button and opens the new-file page with only the file name
  filled in.
- AC11 [trace: V4 → AC11] — When a connected project's default branch is closed to the owner's
  web commits (recorded per repository in `config/projects.json`, from EXP-004), then the link
  for that repository targets the new-file page so the owner commits to a new branch and opens a
  pull request, and the desk says so before opening it.

**Team, pipeline, planning, time (D3.3, D3.4, D4.2, D3.5)**
- AC12 [trace: V4 → AC12] — When the owner opens a project's pipeline view, then it shows the
  project's v3 stage, the item and role at work now (the latest dispatch with no recorded
  outcome), and what comes next (the next item in its queue order), each with the time it was
  last recorded.
- AC13 [trace: V4 → AC13] — When the owner opens "Work ahead", then it lists the open,
  not-yet-dispatched items of every connected project in one list. When the owner reorders it
  and/or sets a "not before" date and time on items and taps "Record plan", then the desk opens a
  prefilled new-file link in Service-Desk for `docs/planning/<YYYY-MM-DD>T<HHMM>Z.md` in J4's
  form. Until that file is on Service-Desk's default branch, the desk labels the plan "Draft, not
  recorded"; once it is, the desk shows it as the current plan. No agent acts on it
  automatically; the Chief of Staff carries it out (owner's ruling of 2026-10-04).
- AC14 [trace: V4 → AC14] — When the owner opens "Time asked of you" for a project, then it lists
  each card of the last 30 days with the time it was raised (commit time of the card file), the
  time it was answered (commit time of the answer file), and the wait between; open cards show
  their wait so far; a summary line gives the count and median wait for the last 14 days.

**Trust, measurement and upkeep (D5, V1–V3 measurement)**
- AC15 [trace: V4 → AC15] — When any request reaches the desk's function without a valid
  `Cf-Access-Jwt-Assertion` for the owner's email address (missing, expired, wrong audience,
  wrong signature, other email), then it answers 403 and makes no GitHub call; and both the
  `pages.dev` address and every custom domain prompt for Access login before anything is served.
  The Reviewer's security review of the login and the read token's handling (D5.2) has passed

- AC16 [trace: V1 → AC16, V2 → AC16] — When the desk is used during a week, then on the device in
  use it records each open window's start and end, and for each flagged item the time it was first

  offers a prefilled link that commits the previous week's figures to
  `docs/metrics/<YYYY>-W<ww>.md` in Service-Desk, in J5's form. Nothing of this is stored on
  Cloudflare.
- AC17 [trace: V4 → AC17] — When the owner approves launch (and S-002 is accepted), then the
  `needs-you` production deployment serves the desk at its `pages.dev` address and custom domains,
  the previous Operations-Hub deployment remains available by rollback, and Operations-Hub's
  repository is archived by the owner.
- AC18 [trace: V3 → AC18] — When the owner wants to add a connected project, then the operating
  notes (D6.3) give the steps: one entry in `config/projects.json` and one repository added to the
  read token; nothing else changes, and a 6th entry is refused with a message saying 5 is the limit.
- AC19 [trace: V3 → AC19] — When the desk is open for 16 hours in a day with 5 connected projects,
  then the function stays within the Free plan: fewer than 10,000 function requests that day,
  no Error 1027, and no Error 1102 on steady polls (spend ceiling $0, PROJECT.md §5; figures in
  "Facts relied on").

## Join sheets

- **J1 — GitHub REST → desk function (reader).** The function sends, per connected project, at
  most 30 outbound requests per invocation (fixed batch size; under the brief's 40 and leaving 20
  of Free's 50 for redirect hops), each `GET` with `Authorization: Bearer <read token>`,
  `Accept: application/vnd.github+json`, and `If-None-Match: <etag>` when it holds one. A steady
  poll is exactly three requests: the default branch head
  (`GET /repos/{o}/{r}/branches/{default}`), open pull requests (`GET /repos/{o}/{r}/pulls?state=open`),
  and check runs on the head (`GET /repos/{o}/{r}/commits/{sha}/check-runs`). Only when one of
  these changes does it read records (J2). ETags are held by the page and sent back with each call
  (J6), so the function stores nothing.
  Awkward cases: 304 on all three (nothing read, returns "unchanged"); 401/403 (token expired or
  missing permission: project marked can't-read, reason "token"); 403/429 with rate-limit headers
  (reason "rate limit", next poll waits until the reset time); 404 on a records directory (treat
  as empty, not as an error); a seventh connection queues (F-cf-workers-07), so a batch of 30
  runs in waves of six; redirect hops count against 50 (F-cf-workers-02); a cold load needs more
  than 30 requests, so the page makes several batched calls and the project stays "Checking…"
  until all return.
  A test marked `join-test: S-001/J1` covers it.

- **J2 — Repository records → read model (per project).** Paths read on the default branch:
  `queue/*.md` (cards), `decisions/<item>/*.md` (answers), and the status, sprint and dispatch-log
  files at the paths named in `config/projects.json` for that project (J7), so a path change is a
  config edit. A card file name (without `.md`) is split by: `<item>` = the leading match of
  `^[A-Z]+-[0-9]+`; `<n>` = the trailing match of `-([0-9]+)$`; `<gate>` = what lies between,
  without its edge hyphens. Its answer is `decisions/<item>/<gate>-<n>.md`. The answer's verdict is the text
  after `Decision: ` on its first line.
  Examples: `queue/Q-003-failure-1.md` → item `Q-003`, gate `failure`, n `1` → answer
  `decisions/Q-003/failure-1.md`. `queue/P-001-dor-fail-2.md` → item `P-001`, gate `dor-fail`,
  n `2` → `decisions/P-001/dor-fail-2.md` (exists in this pack, verdict `resubmit`).
  Awkward cases: a gate containing hyphens (`dor-fail`, handled by taking item and n from the
  ends); a queue file not matching the pattern (shown as activity with a "can't parse" note,
  never flagged, never silently dropped); an answer file with extra lines after the first
  (`decisions/P-001/dor-fail-2.md` has a `Proxy:` line and prose: only line 1 is read); an answer
  committed before the card (still counts as answered); a card file deleted without an answer
  (no longer flagged; shown in activity as "withdrawn").
  A test marked `join-test: S-001/J2` covers it.

- **J3 — Desk page → GitHub new-file page (card answer).** URL:
  `https://github.com/<owner>/<repo>/new/<branch>?filename=<path>&value=<content>`, every
  parameter percent-encoded (UTF-8). `<path>` = `decisions/<item>/<gate>-<n>.md`. `<content>` =
  `Decision: <option>\n` where `<option>` is the card's option word exactly as the card lists it,
  then, if the owner typed a note, a blank line and the note. Example for card
  `queue/P-001-dor-4.md`, option `build`, no note:
  `https://github.com/<owner>/Service-Desk/new/main?filename=decisions%2FP-001%2Fdor-4.md&value=Decision%3A%20build%0A`.
  The `filename` parameter is described by GitHub (F-gh-05, B). The content parameter is
  undocumented; its name `value` is the one EXP-004 confirms (C until then); if EXP-004 finds a
  different name, that name replaces `value` here before freeze.
  Awkward cases: a note with `&`, `#`, `%`, emoji or newlines (encoded; checked by round trip);
  total URL over 6,000 characters (AC10 fallback); an answer file that already exists (GitHub
  refuses or the owner edits; the desk shows "already answered: <verdict>" before offering the
  link); repository whose default branch is not `main` (taken from J1's branch read).
  A test marked `join-test: S-001/J3` covers it.

- **J4 — Desk page → planning record → Chief of Staff.** File
  `docs/planning/<YYYY-MM-DD>T<HHMM>Z.md` in Service-Desk, committed by the owner through a J3-form
  link. Content:
  ```
  Plan: <YYYY-MM-DD>T<HHMM>Z
  Supersedes: <previous plan file name, or none>

  | Order | Project | Item | Not before (UTC) |
  |---|---|---|---|
  | 1 | Service-Desk | P-002 | 2026-11-02T09:00Z |
  | 2 | Personal-Org-Operating-Model | M-014 | — |
  ```
  The latest file by name is the current plan. Awkward cases: an item finished between drafting
  and committing (kept in the record; the Chief of Staff skips it and notes it in the ledger); two
  plans committed in the same minute (second link adds `-2` before `.md`); an empty plan (allowed:
  means "no ordering preference"); a project name with spaces (not possible for repository names;
  rejected by the page).
  A test marked `join-test: S-001/J4` covers it.

- **J5 — Device record → weekly metrics file → Chief of Staff's weekly check.** Stored on the
  device in the browser's local storage under key `desk-metrics-v1`. Committed weekly to
  `docs/metrics/<YYYY>-W<ww>.md` (ISO week, e.g. `2026-W46`) in Service-Desk. Content:
  ```
  Week: 2026-W46   Device: phone
  ## Open windows (UTC)
  | Start | End |
  |---|---|
  | 2026-11-10T07:02:11Z | 2026-11-10T07:09:40Z |
  ## First shown
  | Project | Item | First shown (UTC) |
  |---|---|---|
  | Service-Desk | queue/P-002-dor-1.md | 2026-11-10T07:03:05Z |
  ## Didn't need me
  | Project | Item | Marked (UTC) |
  |---|---|---|
  ```
  The Chief of Staff's V1 count: cards whose commit time falls inside an open window and whose
  first-shown time is more than 5 minutes later, or absent while windows continued. V2 count: rows
  under "Didn't need me". Awkward cases: two devices in one week (one file per device:
  `<YYYY>-W<ww>-<device>.md`); a window still open at the week's end (split at Monday 00:00 UTC);
  local storage cleared (the file says "records from <date>"); the owner skips a week (next
  offer covers every un-committed week, one file each); over-long record for one link (AC10 copy
  fallback).
  A test marked `join-test: S-001/J5` covers it.

- **J6 — Desk page ↔ desk function.** `GET /api/project/<name>?batch=<k>` with header
  `X-Desk-Etags: <base64 JSON {url: etag}>`; response JSON:
  `{ "project": "<name>", "readAt": "<ISO UTC>", "status": "ok" | "unchanged" | "cant-read",
  "reason": null | "token" | "rate-limit" | "github" | "parse", "retryAfter": <seconds|null>,
  "etags": {url: etag}, "more": <bool>, "cards": [{ "path", "item", "gate", "n", "title",
  "options": [..], "raisedAt", "answeredAt": null | "<ISO>", "verdict": null | "<word>" }],
  "prs": [...], "ci": { "sha", "conclusion" }, "status": {...}, "sprint": {...},
  "dispatch": {...} }`. `more: true` means the page must call again with `batch=k+1` before the
  project counts as read (AC2).
  Awkward cases: function returns 403 (Access JWT invalid: page shows "Signed out", not "Quiet");
  network failure (counts toward AC3's 3 minutes); `etags` header too large (page drops the
  oldest and accepts a full read).
  A test marked `join-test: S-001/J6` covers it.

- **J7 — `config/projects.json` → function and page.** Committed in Service-Desk, read at build.
  Form: `[{ "name": "Service-Desk", "repo": "<owner>/Service-Desk", "webCommitsToDefault": true,
  "contentPrefill": true, "paths": { "status": "<path>", "sprint": "<path>", "dispatchLog":
  "<path>" } }]`, at most 5 entries. Awkward cases: 6 entries (build fails with message, AC18);
  a repository the token can't read (AC3 at run time, not a build failure); a missing path entry
  (that panel says "not configured").
  A test marked `join-test: S-001/J7` covers it.

- **J8 — Cloudflare Access → desk function.** Header `Cf-Access-Jwt-Assertion`, validated with
  the team's public keys for signature, expiry, the application's audience tag, and `email` equal
  to the owner's address (F-auth-04, A). The owner's address and audience tag are settings the
  owner enters by hand. Awkward cases in AC15. A test marked `join-test: S-001/J8` covers it.

## Facts relied on (each with evidence)
- Pages Functions run on Workers and count against the Workers quota; identical runtime limits
  are not documented — evidence: library/facts/F-cf-06.md:4 (A). Hence EXP-001 measures on a
  Pages project.
- Free plan: 100,000 requests a day; Error 1027 beyond — evidence: library/F-cf-workers-05.md:8
  (A). AC19's arithmetic (E): 5 projects × 60 polls/h × 16 h = 4,800 steady calls, plus cold
  loads at about 5 projects × 3 calls × 10 openings = 150, under 10,000.
- Free plan: 10 ms CPU per request, network waits excluded; Error 1102 beyond — evidence:
  library/F-cf-workers-01.md:8 (A). Occasional overages tolerated — library/F-cf-workers-08.md:9 (B).
- 50 external subrequests per invocation on Free; redirect hops count — evidence:
  library/F-cf-workers-02.md:8 (A).
- Six connections waiting for headers at once; a seventh queues — evidence:
  library/F-cf-workers-03.md:8 (A), library/F-cf-workers-07.md:9 (B).
- Free-plan HTTP wall-time limit: not filed — evidence: library/F-cf-workers-03.md:8 (NOT filed).
  EXP-001 measures it.
- A 304 with an Authorization header doesn't count against GitHub's primary limit; PAT limit
  5,000/h — evidence: library/Q-004-facts.md:9, :8 (A). Steady load 3 × 5 × 60 = 900/h (E,
  PAT-Q004-1, library/Q-004-facts.md:18).
- Webhooks can be minutes late and aren't redelivered, so the design polls — evidence:
  library/Q-004-facts.md:6, :14, :15 (A/B).
- `?filename=` prefills the new-file name; no content parameter documented — evidence:
  library/F-gh-05.md:8 (B). Owner's own use of content-prefilled links from phone browser and app:
  docs/PROJECT.md:318-320 (C, observed by the owner). EXP-004 confirms per repository.
- Over-long query links on other GitHub pages return 414; no limit documented for new-file —
  evidence: library/F-gh-06.md:8 (A). The 6,000-character cap in AC10 is our own margin (E),
  checked in EXP-004.
- Commit step offers current or new branch; push rulesets may block creating a file; protected
  branches block web edits — evidence: library/F-gh-07.md:8 (A), library/F-gh-10.md:9 (A).
- Access: validate the JWT with the public key, prefer the header — library/F-auth-04.md:8 (A).
  A One-time-PIN-only policy lets anyone in; policies can name emails — library/F-auth-02.md:8 (A).
  Pages' "Enable access policy" covers previews only; `*.pages.dev` and each custom domain need
  their own — library/facts/F-cf-04.md:4 (A).
- A production deployment (Git or `wrangler pages deploy`) changes what `pages.dev` and custom
  domains serve; rollback is instant — library/facts/F-cf-02.md:4 (A). A project can't switch
  deployment method — library/facts/F-cf-03.md:4 (B). Which method `needs-you` uses: EXP-002.
- Answer files start `Decision: <word>` — evidence: decisions/P-001/dor-4.md:1,
  decisions/P-001/failure-5.md:1, decisions/P-001/dor-fail-2.md:1 (this pack).
- Known limits:
  - The card/answer pairing rule (J2) and the paths of status, sprint and dispatch-log files are
    inferred, not quoted from the model's documents (C); they are config, and the Check author's
    join tests use real files from Service-Desk.
  - The content prefill parameter is undocumented (C); GitHub could change it; AC10 is the
    fallback.
  - Whether the CPU and wall time of a cold-load batch fit Free: EXP-001 (O3).

## Risks and mitigations
- **CPU per cold-load batch exceeds 10 ms (O3).** EXP-001 measures it before Build ends; fallback
  per the owner's ruling (decisions/questions/P-001-o3-define.md): smaller batches (the batch size
  is one constant), else the $5 Paid plan with a new ceiling from the owner.
- **`needs-you` is Git-integrated (O5).** EXP-002; fallback per the owner's ruling
  (decisions/questions/P-001-o5-define.md): a new Pages project and a permanent redirect.
- **GitHub drops the content parameter.** AC10's copy fallback; the flag in J7 lets the owner
  switch a repository to it without a rebuild of logic.
- **A missed card while the desk shows "Quiet" (the owner's worst case).** AC2 and AC3 make
  "Quiet" require a fresh successful read of every project; parse failures show, never vanish (J2).
- **Too many agents for T1.** Build runs with at most two builder or reviewer agents at once
  (PROJECT.md §5); the Orchestrator script does not count. More needs the owner's T2 ruling.
- **Read token leaks.** It is fine-grained, read-only, limited to the connected repositories
  (L-F5), held only as a Cloudflare secret the owner sets by hand, and never sent to the page or a
  model (PROJECT.md §5); D5.2 reviews it.
- **Touching the live page before launch.** The preview is a separate Pages project
  (`service-desk-preview`, created by the owner); nothing deploys to `needs-you` before AC17
  (L-0115).
