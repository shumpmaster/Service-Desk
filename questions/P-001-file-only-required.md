# Ruling needed: Which asks get filed as questions in GitHub?

Milestone: none (a change to how asks are recorded, across both projects; it serves no single milestone)

WHY: Since model 3.5.0 (17 October), every ruling put to you is filed as a question before it is asked, then answered in a second record. For an ask put to you in a session and answered there, that means two extra pull requests, and the question sits on the desk as a live decision until the answer lands, which is the stale link you hit. You said, on 18 October: "A question, should only be recorded in GitHub if it’s actually required by the operating model." The model requires it today, so changing this is a change to the model.
OPTIONS:
  A. Record session asks once, as the answer — An ask put to you in a session and answered there is recorded once, as its answer with your words, with no question filed first. A question is still filed when you aren't there to answer it now, so it waits on the desk (an ask left open, a card, anything due to default). This needs a change to the operating model, made under its own process, then synced here.
  B. Keep filing every ask — As today.
RECOMMENDATION: A — every ruling is still recorded in your words, it halves the pull requests, and the desk never shows a question you've already answered.
RISK CLASS: R0   REVERSIBILITY: reversible   BLAST RADIUS: how asks are recorded in every project on the model; the desk's Queue shows only asks that truly wait on you
DEFAULT: B   TIMEOUT: 48
